User Guide

What is VEIL?

VEIL hides encrypted text inside ordinary-looking images using LSB steganography. Anyone who intercepts the image sees only a normal emoji sticker or photo. The hidden message is invisible and protected by strong encryption.

Everything runs locally in your browser. No data is ever sent to any server.

Step 1 — Key Exchange (one-time setup)

Both parties must establish a shared key using Elliptic-Curve Diffie–Hellman (ECDH P-256). Neither needs to know the other's secret — each derives the same shared key independently.

Alice

1. Opens KEY EXCHANGE tab
2. Clicks Generate My Keys
3. Picks an emoji cover
4. Clicks Download Key Image
5. Sends the PNG to Bob
(email, any messenger — not secret)

Bob

1. Opens KEY EXCHANGE tab
2. Clicks Generate My Keys
3. Drops Alice's image under "Peer's Key"
4. Shared secret derived automatically
5. Downloads his own key image
6. Sends it to Alice

Alice drops Bob's image → Shared Key Ready ✓ on both sides. Both will see the same Key Fingerprint — verify it verbally or via a separate channel to confirm no interception.

💡 About the Key Fingerprint: it is the first 4 bytes of SHA-256(shared_secret), displayed as hex pairs (e.g. A3 F2 B8 C1). It is a hash of the derived secret — not raw key bytes — so it reveals nothing about the secret itself. If both parties see the same fingerprint, the key exchange was successful.
⚠ Keys are saved in browser localStorage and survive page refresh. Click Clear Session to remove them. On a shared computer, always clear the session after use.

Step 2 — Sending a Message (Encode tab)

  1. Go to the Encode tab.
  2. Select a cover image (emoji preset or your own photo). PNG is recommended.
  3. If the DH key is active, it is used automatically (🔑 DH Key Active). Otherwise enter a shared password.
  4. Type your message in Text to Hide.
  5. Click Encode & Download. The image file downloads.
  6. Send the downloaded file to your contact.
⚠ Always send as a file/document, not as an inline photo. Most messengers re-compress images to JPEG, destroying hidden data.
Telegram: 📎 → File. WhatsApp: share as document.

Step 3 — Reading a Message (Decode tab)

  1. Go to the Decode tab.
  2. Drop or select the received PNG/GIF file.
  3. DH key or password — same as encoding.
  4. Click Decode Message. The text appears below.

Format Notes

  • PNG — Lossless. Works everywhere when sent as file. Recommended.
  • GIF — Works in WhatsApp and Viber. Fails in Telegram (converts to MP4).
  • Never use the messenger's "photo" upload — always use "file" mode.

Technical Details

  • Key exchange: ECDH P-256 via Web Crypto API. 256-bit shared secret via deriveBits.
  • Key fingerprint: SHA-256(shared_secret)[0..3] as hex — a verifiable digest, not raw key material.
  • Encryption: AES-256-GCM. Key derived with PBKDF2 (100,000 × SHA-256). Fresh random salt (16 B) + IV (12 B) per message. GCM auth tag prevents tampering.
  • PNG stego: LSB of R,G,B — 3 bits/pixel. 500×500 px ≈ 90 KB capacity.
  • GIF stego: Median-cut to 128 colors, palette-pair encoding (LSB of index). 1 bit/pixel.
  • Header: "VEIL"(4) + length(4) + salt(16) + IV(12) = 36 bytes overhead.

Що таке VEIL?

VEIL приховує зашифрований текст всередині звичайних зображень за допомогою LSB-стеганографії. Будь-хто, хто перехопить зображення, побачить лише звичайний emoji-стікер або фото. Приховане повідомлення невидиме та захищене стійким шифруванням.

Усе виконується локально у вашому браузері. Жодні дані не передаються на сервери.

Крок 1 — Обмін ключами (одноразово)

Обидва учасники повинні встановити спільний ключ за допомогою ECDH P-256. Нікому не потрібно знати секрет іншого — кожен незалежно виводить однаковий спільний ключ.

Аліса

1. Відкриває вкладку «Обмін ключами»
2. Натискає Згенерувати ключі
3. Вибирає emoji-обкладинку
4. Натискає Завантажити ключ-зображення
5. Надсилає PNG Бобу
(email, будь-який месенджер — не секрет)

Боб

1. Відкриває вкладку «Обмін ключами»
2. Натискає Згенерувати ключі
3. Завантажує зображення Аліси у «Ключ від контакту»
4. Спільний секрет виводиться автоматично
5. Завантажує своє ключ-зображення
6. Надсилає його Алісі

Аліса завантажує зображення Боба → Спільний ключ готовий ✓ у обох. Обидва бачать однаковий Відбиток ключа — звірте його голосово або іншим каналом, щоб підтвердити відсутність перехоплення.

💡 Про відбиток ключа: це перші 4 байти SHA-256(спільний_секрет), відображені як hex-пари (наприклад A3 F2 B8 C1). Це хеш похідного секрету — не самі байти ключа — тому він нічого не розкриває про секрет. Якщо обидва учасники бачать однаковий відбиток, обмін ключами пройшов успішно.
⚠ Ключі зберігаються у localStorage браузера та виживають після перезавантаження. Натисніть Очистити сесію для їх видалення. На спільному комп'ютері завжди очищуйте сесію після використання.

Крок 2 — Надсилання повідомлення (вкладка Шифрування)

  1. Перейдіть на вкладку Шифрування.
  2. Виберіть зображення-носій (emoji-пресет або своє фото). Рекомендується PNG.
  3. Якщо DH-ключ активний, він використовується автоматично (🔑 DH-ключ активний). Інакше введіть спільний пароль.
  4. Введіть повідомлення у полі Текст для приховування.
  5. Натисніть Зашифрувати та завантажити. Файл зображення буде завантажено.
  6. Надішліть завантажений файл контакту.
⚠ Завжди надсилайте як файл/документ, а не як вбудоване фото. Більшість месенджерів повторно стискають зображення у JPEG, знищуючи приховані дані.
Telegram: 📎 → Файл. WhatsApp: поділіться як документ.

Крок 3 — Читання повідомлення (вкладка Розшифрування)

  1. Перейдіть на вкладку Розшифрування.
  2. Перетягніть або виберіть отриманий PNG/GIF файл.
  3. DH-ключ або пароль — так само, як при шифруванні.
  4. Натисніть Розшифрувати. Текст з'явиться нижче.

Примітки щодо форматів

  • PNG — Без втрат. Працює скрізь при надсиланні як файл. Рекомендується.
  • GIF — Працює у WhatsApp та Viber. Не Telegram (конвертує у MP4).
  • Ніколи не використовуйте режим «фото» — завжди режим «файл».

Технічні деталі

  • Обмін ключами: ECDH P-256 через Web Crypto API. 256-бітний спільний секрет через deriveBits.
  • Відбиток ключа: SHA-256(спільний_секрет)[0..3] як hex — верифікований дайджест, не самі байти ключа.
  • Шифрування: AES-256-GCM. Ключ через PBKDF2 (100 000 × SHA-256). Нові випадкові сіль (16 Б) + IV (12 Б) для кожного повідомлення. Тег GCM запобігає підробленню.
  • PNG-стего: LSB каналів R,G,B — 3 біти/піксель. 500×500 пікселів ≈ 90 КБ ємності.
  • GIF-стего: Median-cut до 128 кольорів, кодування парами палітри (LSB індексу). 1 біт/піксель.
  • Заголовок: "VEIL"(4) + довжина(4) + сіль(16) + IV(12) = 36 байтів накладних витрат.
